chính thức.

# 7. Data Model đề xuất

## 7.1. Nguyên tắc thiết kế

-   JSON là nguồn dữ liệu nội dung duy nhất.
-   Tách dữ liệu cá nhân, kinh nghiệm, dự án, kỹ năng và học vấn thành
    các file riêng.
-   Mỗi entity có `id` ổn định; không dùng vị trí phần tử trong mảng làm
    định danh.
-   Nội dung có thể hỗ trợ nhiều ngôn ngữ bằng object
    `{ "vi": "...", "en": "..." }`.
-   Profile ứng tuyển chỉ cấu hình cách trình bày và lựa chọn nội dung;
    không nhân bản dữ liệu gốc.
-   Theme và display mode độc lập với profile.
-   Chỉ đưa dữ liệu đã xác nhận vào bản public.

# 8. Kế hoạch triển khai cho Google Antigravity

## 8.1. Mục tiêu sản phẩm

Xây dựng website CV/Portfolio cá nhân có thể:

-   Hiển thị hồ sơ nghề nghiệp và các dự án tiêu biểu.
-   Chuyển đổi profile ứng tuyển.
-   Chuyển đổi tiếng Việt/tiếng Anh.
-   Chuyển đổi theme.
-   Chuyển đổi giữa Portfolio View và Resume View.
-   In hoặc lưu CV thành PDF bằng trình duyệt.
-   Responsive trên desktop, tablet và mobile.
-   Deploy trực tiếp lên GitHub Pages.

## 8.2. Ràng buộc kiến trúc

**Bắt buộc:**

-   HTML5, CSS3 và Vanilla JavaScript sử dụng ES Modules.
-   JSON là nguồn dữ liệu.
-   Không backend, không database, không API server.
-   Không framework frontend.
-   Không yêu cầu bước build/bundle để deploy.
-   Không lưu nội dung CV trực tiếp trong JavaScript hoặc HTML.
-   Không nhúng GitHub Personal Access Token hoặc secret vào source
    code.
-   Không triển khai editor trên website ở phiên bản này. Nội dung được
    chỉnh sửa trực tiếp trong JSON tại local, sau đó commit/push lên
    GitHub.
-   GitHub Pages phục vụ website static.

**Có thể sử dụng:**

-   Google Fonts hoặc font local có giấy phép phù hợp.
-   Lucide Icons hoặc SVG inline.
-   CSS Print và `window.print()` để xuất PDF.
-   GitHub Actions nếu cần tự động kiểm tra và deploy; không bắt buộc.

## 8.4. Thiết kế URL

Sử dụng query parameters, không cần client-side router phức tạp:

``` text
/
?profile=dotnet-backend
?profile=fullstack
?lang=en
?theme=dark
?view=resume
?profile=fullstack&lang=en&theme=dark&view=resume
```

Quy tắc:

-   Không có query: dùng cấu hình mặc định.
-   Profile, language, theme hoặc view không hợp lệ: fallback về giá trị
    mặc định.
-   Không reload toàn trang khi người dùng chuyển cấu hình nếu không cần
    thiết.
-   URL phải phản ánh trạng thái hiện tại để người dùng chia sẻ đúng
    phiên bản CV.

## 8.5. Các phase triển khai

### Phase 0 -- Foundation

**Mục tiêu:** Tạo bộ khung static và cơ chế nạp dữ liệu.

Task:

1.  Tạo cấu trúc thư mục và `index.html`.
2.  Tạo CSS nền tảng, reset và design tokens.
3.  Thiết lập JavaScript ES Modules.
4.  Implement `data-service.js` để tải JSON bằng `fetch()`.
5.  Validate dữ liệu bắt buộc và xử lý lỗi khi JSON không tải được.
6.  Implement state/config cơ bản.
7.  Chạy local bằng HTTP server.

Acceptance criteria:

-   Website chạy được trên local HTTP server.
-   Nạp được tất cả JSON.
-   Không phát sinh lỗi console.
-   Có thông báo/fallback rõ ràng nếu dữ liệu không hợp lệ.

### Phase 1 -- Public Portfolio

**Mục tiêu:** Hoàn thiện website portfolio mặc định.

Các section:

1.  Header và navigation.
2.  Hero: tên, headline, summary, thông tin liên hệ.
3.  Technical Skills.
4.  Work Experience.
5.  Featured Projects.
6.  Education & Certificates.
7.  Footer/Contact.

Acceptance criteria:

-   Nội dung được render từ JSON.
-   Không hardcode dữ liệu cá nhân trong component.
-   Responsive trên desktop, tablet và mobile.
-   Có trạng thái khi thiếu dữ liệu tùy chọn.

### Phase 2 -- Resume View & PDF

**Mục tiêu:** Có giao diện CV gọn, phù hợp gửi nhà tuyển dụng.

Task:

-   Tạo Resume View tối ưu cho 1--2 trang A4 nếu nội dung thực tế cho
    phép.
-   Tạo CSS Print riêng.
-   Ẩn navigation và các control không cần thiết khi in.
-   Kiểm soát page break, màu sắc, font và link.
-   Dùng `window.print()` để người dùng chọn Save as PDF.

Acceptance criteria:

-   In được PDF tiếng Việt không lỗi font.
-   Không bị cắt nội dung quan trọng.
-   Link liên hệ có thể truy cập.
-   Kiểm tra bằng Chrome/Edge.

### Phase 3 -- Multi-profile & Localization

**Mục tiêu:** Dùng chung dữ liệu để tạo các phiên bản CV.

Task:

-   Đọc profile từ `config/profiles.json`.
-   Lọc section, project và thứ tự nhóm skill theo profile.
-   Hỗ trợ tiếng Việt và tiếng Anh.
-   Xử lý fallback khi thiếu bản dịch.

Acceptance criteria:

-   Chuyển profile không làm mất dữ liệu gốc.
-   Chuyển ngôn ngữ không cần tạo hai bộ dữ liệu riêng.
-   URL có thể chia sẻ đúng profile/ngôn ngữ.

### Phase 4 -- Theme & Display

**Mục tiêu:** Tách giao diện khỏi dữ liệu và hỗ trợ nhiều cách hiển thị.

Task:

-   Implement theme service.
-   Tạo Minimal theme trước.
-   Tạo Dark Developer theme sau khi Minimal ổn định.
-   Hỗ trợ Portfolio View và Resume View.
-   Đảm bảo theme không làm hỏng bản in.

Acceptance criteria:

-   Chuyển theme không thay đổi dữ liệu.
-   Theme mặc định hoạt động khi query không hợp lệ.
-   Resume View vẫn đọc được khi in.

### Phase 5 -- SEO, Accessibility & Polish

Task:

-   Metadata title, description, Open Graph.
-   Semantic HTML.
-   Keyboard navigation và focus state.
-   Alt text cho hình ảnh.
-   Kiểm tra contrast, responsive và hiệu năng tải.
-   Favicon và social preview.

Acceptance criteria:

-   Không có lỗi accessibility cơ bản.
-   Metadata đúng theo profile/ngôn ngữ mặc định.
-   Website hoạt động tốt trên màn hình nhỏ.

### Phase 6 -- GitHub Pages Deployment

Task:

-   Tạo repository GitHub.
-   Cấu hình Pages deploy từ branch hoặc GitHub Actions.
-   Kiểm tra base path nếu dùng project repository.
-   Kiểm tra đường dẫn asset/JSON khi deploy.
-   Viết hướng dẫn cập nhật nội dung.

Acceptance criteria:

-   Website truy cập được bằng URL GitHub Pages.
-   Không có lỗi 404 đối với JSON, CSS, JS và ảnh.
-   Query parameters hoạt động.
-   Có thể cập nhật CV bằng cách sửa JSON, commit và push.

## 8.6. Quy tắc làm việc cho AI Agent

1.  Đọc `my-profile-plan.md` trước khi triển khai.
2.  Chỉ đọc các phần liên quan đến task hiện tại; không cần nạp lại toàn

# 9. Việc cần xác nhận trước khi chốt CV

Các câu hỏi dưới đây ảnh hưởng trực tiếp đến độ tin cậy của CV Senior.
Không cần trả lời tất cả ngay; ưu tiên các mục có thể chứng minh bằng ví
dụ thực tế.

1.  **Chức danh và vai trò tại MISA:** Chức danh chính thức là gì? Bắt
    đầu làm Advisor từ tháng/năm nào? Vai trò phụ trách SA cụ thể đến
    đâu?
2.  **Bài toán báo cáo 90%:** Con số 90% dựa trên bao nhiêu mẫu báo cáo,
    do ai đánh giá và có thể công khai không?
3.  **Thiết kế hệ thống:** Bạn đã trực tiếp thiết kế module, API,
    database schema, workflow hoặc lựa chọn kiến trúc nào? Hãy nêu 1--2
    ví dụ.
4.  **Hiệu năng:** Đã xử lý vấn đề nào, nguyên nhân và kết quả trước/sau
    ra sao?
5.  **Security:** Đã thực hiện những hạng mục rà soát hoặc khắc phục
    nào? Có thể mô tả mà không tiết lộ thông tin nội bộ không?
6.  **AI Coding:** Quy trình/skill/wiki đã giúp cải thiện điều gì? Có số
    liệu hoặc ví dụ cụ thể không?
7.  **Công nghệ:** Mức độ sử dụng thực tế của Next.js, Kafka,
    PostgreSQL, Playwright và Integration Testing?
8.  **Dự án cá nhân:** SnapFox và TORVEN có thể công khai tên, ảnh chụp,
    URL hoặc mô tả nghiệp vụ đến mức nào?
9.  **Liên kết:** Có LinkedIn, GitHub hoặc website dự án nào muốn đưa
    vào CV không?
10. **Tiếng Anh:** B1 là chứng chỉ chính thức hay mức tự đánh giá? Năm
    cấp chứng chỉ?

## Những nội dung nên loại bỏ hoặc hạn chế

-   Không đưa "vui vẻ, hòa đồng" thành bullet kỹ năng chính.
-   Không đưa FileZilla vào nhóm kỹ năng nổi bật.
-   Không đưa dự án Siêu thị bản vẽ nhà vào CV chính nếu cần giữ CV
    ngắn.
-   Không khẳng định "Solution Architect" nếu vai trò thực tế là phụ
    trách một số đầu việc SA.
-   Không ghi mức độ thành thạo công nghệ khi chưa có căn cứ.
-   Không công khai thông tin nghiệp vụ, dữ liệu khách hàng hoặc chi
    tiết nội bộ của MISA.

# 10. Hướng dẫn sử dụng và cập nhật

## Khi phát triển

1.  Đưa `my-profile-plan.md` vào thư mục gốc repository.
2.  Yêu cầu Antigravity đọc phần định vị, Data Model và Implementation
    Plan.
3.  Bắt đầu từ Phase 0, không yêu cầu AI triển khai toàn bộ trong một
    lần.
4.  Review JSON và giao diện sau mỗi phase.

## Khi cập nhật CV

1.  Chỉnh file JSON tương ứng tại local.
2.  Kiểm tra website trên local HTTP server.
3.  Kiểm tra Portfolio View và Resume View.
4.  In thử PDF.
5.  Commit và push lên GitHub.
6.  Kiểm tra website sau deploy.

## Lưu ý kỹ thuật

-   Không mở trực tiếp `index.html` bằng `file://` nếu ứng dụng dùng
    `fetch()` để đọc JSON; cần chạy qua HTTP server local.
-   Với dự án thuần static, có thể dùng VS Code Live Server hoặc Python
    HTTP Server để phát triển.
-   GitHub Pages chỉ host file tĩnh; mọi dữ liệu trong repository public
    đều có thể được truy cập.
-   Không đưa số điện thoại/email khác dự định công khai, secret, token,
    dữ liệu khách hàng hoặc thông tin nội bộ vào repository.
-   GitHub Actions không bắt buộc nếu chọn deploy trực tiếp từ branch.
